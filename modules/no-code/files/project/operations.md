# Operations cycle

The recurring cycle of {{PROJECT_NAME}}, in place of sprints. Default cadence: weekly, with a monthly close. Session start and close follow `working-agreement.md`.

To run the weekly cycle on a schedule, ask for a routine (`/schedule`) that drafts the cycle and files the drafts. A routine sends nothing: each item still waits for approval in `deliverables.md`.

> ADAPT: replace the example steps with this project's real recurring work (client onboarding checks, publishing, invoicing, a monthly review). Keep each step's approver.

## Weekly cycle

| Step | Agent prepares | {{OWNER}} approves |
|---|---|---|
| Review open items and deliverables in progress | a one-screen status: done, late, blocked | next week's priorities |
| Draft the outputs due | drafts in `deliverables.md` | each draft before it is sent |
| Update `plan.md` and the open questions in `decisions.md` | the new state | nothing, unless a default changed |
| Refresh `owner.md` | the current list, each item with a default | the answers |

## Monthly cycle

| Step | Agent prepares | {{OWNER}} approves |
|---|---|---|
| Close the month: shipped, slipped, hours and spend against the ceiling | numbers with dates and basis | the summary |
| Review the beliefs and kill lines in `brief.md` | each belief's status, as counts | any change of direction |
| Check vendors and stored data against the brief | open items, expired terms | any new vendor |
| Archive finished work | the list of moves | nothing |

A kill line that reached its read date this month is decided here: stop, pivot or rescope, logged in `decisions.md`.
